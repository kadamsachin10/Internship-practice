# Day 7 – Testing Types

## 1. Black Box Testing

**Meaning:** Testing the application's functionality without needing to know its internal code.

**Who performs it:** Testers commonly perform Black Box Testing. It is not limited to testers only.

**Example:** Testing login functionality by entering valid and invalid credentials and checking the system responses.

## 2. White Box Testing

**Meaning:** Testing internal code, logic, conditions, and execution paths to check whether they work correctly.

**Who performs it:** Developers commonly perform White Box Testing. It is not limited to developers only.

**Example:** A developer checks whether the internal logic and different execution paths of a FASTag module work correctly.

## 3. Grey Box Testing

**Meaning:** Testing application functionality while using some knowledge of its internal workings, such as APIs, databases, or system structure.

**Who performs it:** A tester or other testing professional who has some knowledge of the system's internals can perform Grey Box Testing. Full development knowledge is not always required.

**Example:** A tester logs in through the UI using valid and invalid credentials, then checks API responses and relevant database records to verify that the backend data is correct.

## Quick Comparison

| Testing Type | Main Focus | Internal Knowledge |
|---|---|---|
| Black Box Testing | Inputs, outputs, and functionality | No code knowledge required |
| White Box Testing | Code, logic, conditions, and paths | Detailed code knowledge |
| Grey Box Testing | Functionality plus selected internal details | Partial knowledge of internals |

**Remember:** Positive and negative scenarios can be tested using all three approaches. The main difference is how much internal system knowledge is used.
